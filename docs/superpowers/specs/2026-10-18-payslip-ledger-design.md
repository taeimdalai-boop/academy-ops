# 급여대장(엑셀) → 월급명세서 PDF · 메일 초안 — 설계서

> 작성일: 2026-10-18 · 방식: 현재 방식 · 상위: `2026-10-18-payroll-prototype-design.md`

## 1. 배경

원장님의 실제 업무는 **엑셀 급여대장(직원 1명 = 1행, 지급·공제 항목이 열)** → 직원별 PDF → 메일 발송이다.
실물 명세서(발주처 제공 샘플 1건, `<성명>_급여명세서_<YYYY-MM>.pdf`)는 HTML을 헤드리스 Edge로 인쇄한 A4 1장이다.
과제 제출용은 **워크플로우랩** 이름·로고·문구로, **더미 데이터**로 같은 양식의 PDF를 만든다.

## 2. 실물 양식 (측정값, pt 기준 A4 596×842)

| 영역 | 내용 |
|:---|:---|
| 제목 | "월 급 명 세 서" 25.5pt 굵게 + "PAY STATEMENT" 9.7pt 자간 넓게, 아래 구분선 |
| 회사·직원 블록 (y 98~167) | 로고(54pt) · 회사명 · 사업자등록번호 · 대표자 │ 성명·사원번호·직책·생년월일 │ 지급년월·지급일·입사일·지급구분 |
| 지급내역 / 공제내역 카드 (y 184~481) | 좌우 2장, 각 항목·금액(원) 10행 (빈 행 "-"), 하단 지급총액 / 공제총액 |
| 실지급액 바 (y 490~532) | 진한 배경, "지급총액 - 공제총액", 금액 + "원" |
| 근태 및 기타정보 (y 544~626) | 비고 문장 + 문의 안내 |
| 감사 문구 바 (y 638~668) | 가운데 정렬 1줄 |
| 서명 (y 725~808) | 회사명 + 직인 |

## 3. 입력

| 파일 | 내용 |
|:---|:---|
| `급여대장_YYYY-MM.xlsx` (시트 `급여대장`) | 1행 = 직원 1명. 공통 열: 지급년월·지급일·사원번호·성명·직책·생년월일·입사일·지급구분·이메일·비고 / 지급 항목 열 / 공제 항목 열 / (선택) 지급총액·공제총액·실지급액 |
| `company.yaml` | 회사명·사업자등록번호·대표자·로고·직인·색상·감사 문구·문의 문구·**지급 항목 목록·공제 항목 목록**(열 이름 = 명세서 항목 이름, 순서 = 명세서 순서) |

## 4. 처리

1. 대장 읽기 → 필수 열 검사 (없으면 중단)
2. 직원별 지급·공제 합계 계산 (Decimal). 대장에 합계 열이 있으면 **대조 — 다르면 그 직원 PDF 미생성 + 확인 필요**
3. 항목 10행 초과면 확인 필요(양식이 10행 고정)
4. HTML 렌더 → Edge 헤드리스 `--print-to-pdf` → `<성명>_급여명세서_<YYYY-MM>.pdf` (실물과 같은 파일명 규칙)
5. 메일 초안 `.eml` (PDF 첨부, 본문에 금액 없음) — **발송하지 않음**

## 5. 출력

`out/payslips/YYYY-MM/` : `pdf/*.pdf` · `html/*.html` · `mail/*.eml` · `확인필요.md`

## 6. 예외

| 상황 | 처리 |
|:---|:---|
| 대장 파일·필수 열 없음 | 중단, 종료 코드 1 |
| 회사 설정의 항목이 대장에 열로 없음 | 0원으로 표시하지 않고 중단 (오타 방지) |
| 합계 열 불일치 | 해당 직원 미생성, 확인 필요 |
| 이메일 없음 | PDF는 만들고 메일 초안만 생략, 확인 필요 |
| Edge 없음 | HTML까지만 만들고 종료 코드 3 |

## 7. 한계

- 세금·4대보험 금액은 계산하지 않고 대장 값을 그대로 쓴다(대장이 원천).
- 실제 메일 발송은 하지 않는다 — 원장님(대표) 확인 후 발송.
- PDF 렌더는 Windows Edge에 의존한다.
